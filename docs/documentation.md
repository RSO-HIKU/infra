# Hiku — Infrastructure Overview

## Overview

This document describes the repository's infrastructure-as-code (IaC) layout and usage. The `infra` folder contains Terraform configuration that provisions cloud resources (Azure) required to run the Hiku platform: networking, Kubernetes (AKS), container registry, PostgreSQL, Key Vault, logging, storage for static frontend and functions, and related role assignments and secrets.

## Folder Layout

- `infra/iac/terraform/backends/`
	- Backend configuration snippets used to initialize Terraform remote state. Use these when configuring the `terraform` backend for each environment.

- `infra/iac/terraform/envs/`
	- Each environment has a folder containing a complete Terraform configuration optimized for that environment. Typical files in an `envs/<env>` folder:
		- `main.tf` — core resources and modules.
		- `variables.tf` — input variables and defaults.
		- `terraform.tfvars` — environment-specific values
		- `versions.tf` — required Terraform and provider versions.
		- `outputs.tf` — exported outputs to consume in CI or scripts.
		- `.terraform.lock.hcl` and `.terraform/` — provider lock and initialized working directory (generated by `terraform init`).

- `infra/iac/terraform/modules/`
	- Reusable Terraform modules.

## Providers

- Providers observed in `envs/test/versions.tf`:
	- `hashicorp/azurerm` (~> 4.0) — Azure resources (AKS, Storage, Key Vault, etc.).
	- `cyrilgdn/postgresql` (~> 1.26) — PostgreSQL objects (roles, extensions) inside the managed server.
	- `hashicorp/random` (~> 3.6) — random passwords and secrets.

## Provisioned Resources

The Terraform configuration provisions the following major resource types (`main.tf` file in each `envs/*`):

- Resource Group — single logical container for Azure resources.
- Virtual Network and Subnets — network segmentation for AKS and other services.
- Azure Kubernetes Service (AKS) — the primary cluster for microservices.
- Container Registry (ACR) — private container image registry for CI/CD.
- Key Vault — central secrets store for DB credentials, service credentials, and other secrets.
- Log Analytics Workspace — centralized logging/monitoring for AKS and other resources.
- Public IPs and NAT Gateway — static IP for ingress and outbound NAT.
- Role Assignments — ACR pull role for AKS, Key Vault access roles for services, etc.
- Azure PostgreSQL Flexible Server — managed PostgreSQL instance for the application.
	- Database and DB-level configuration.
	- PostgreSQL extensions installed via the `postgresql` provider: `postgis`, `uuid-ossp`, `pg_trgm`.
	- Per-service DB roles, schemas and grants.
- Azure Storage Accounts
	- Blob storage + containers for application assets.
	- A Storage Account configured as a static website to host the frontend (Found in the file `frontend-static-site.tf`).
- Azure Function App and related hosting/storage.

## Outputs

  The environment outputs (`outputs.tf`) expose useful values for CI and operators, including:
	- `resource_group_name`, `aks_cluster_name`, `acr_name`, `key_vault_name`.
	- `traefik_public_ip`, `traefik_fqdn`, `frontend_static_website_url`.
	- PostgreSQL connection: `postgres_fqdn`, `postgres_db_name`, and sensitive admin/password outputs (sensitive values are marked `sensitive = true`).
	- ACR admin credentials (sensitive) for CI if required.
  
  If needed, secrets can be read from the Key Vault using Azure Portal.

## Environment Configuration

- `terraform.tfvars` is the main place to set environment values. Important example entries:
	- `project = "hiku"`
	- `environment = "test"`
	- `location = "polandcentral"`
	- `services` — map of microservices and their DB users/schemas (used to create per-service DB roles and schemas).

## Terraform Commands

All commands below are executed from the environment folder, for example: `infra/iac/terraform/envs/test`

```powershell
#  Initialize providers and backend
terraform init -backend-config="../../backends/test/test.hcl"

# Validate configuration
terraform validate

# Generate and inspect planned changes
terraform plan -out=tfplan

# Apply the plan
terraform apply tfplan

# To view outputs after apply
terraform output

# To destroy the provisioned resources
terraform destroy
```

## Security & Secrets

- Sensitive values (DB passwords, ACR admin password, etc.) are generated with `random_password` and stored as `sensitive` outputs where possible. The configuration also writes secrets into the provisioned Azure Key Vault.
- Ensure `terraform.tfstate` is not committed (it may contain secrets). It is already included in `.gitignore`
